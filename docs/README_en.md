Public documents distinguish design contracts from results of a particular experiment.

| Category | Entry | Purpose |
| --- | --- | --- |
| Current standards | [v0.1 standards](standard/v0.1/README_en.md) | language, execution contracts, public API |
| Usage/contributing | [usage](development/USAGE_en.md), [development guide](standard/v0.1/DEVELOPMENT_GUIDE_en.md) | install, run, extend, verify |
| Status/evidence | [status](development/STATUS_en.md) | implemented scope, reports, limitations |

LANGUAGE_SPEC defines language; IMPLEMENTATION_WHITEPAPER defines components/API/policies. Examples are under examples; language fixtures under tests/fixtures.

Development/implementation reports are non-normative evidence. Stage reports describe their date, not current universal support. JSON preserves actual model results and intermediate failures rather than guaranteeing quality.

Internal discussions, withdrawn ideas, old schemas, interface snapshots, and delivery records are excluded from the public branch.
