# SkilledGraph v0.1 语言规范

> 2026-10-17：已纳入工具调用、request_input、monty、实验性执行记录和子图引用；具体契约见扩展章节。

状态：当前语言规范。日期：2026-10-17。术语与文档效力见[开发基石](README_cn.md)。本规范定义 Markdown 输入及其图语义；内置代码执行与模型适配见[功能实现白皮书](IMPLEMENTATION_WHITEPAPER_cn.md)。

阅读顺序：§1～§4 定义字符、上下文和文件结构；§5～§7 定义设置、正文提取与转移表；§8～§10 定义控制流、扩展和诊断；§11 列出暂缓功能。

## 1. 语言模型与范围

一个 UTF-8 文件定义一个图，至少一个节点。节点以声明顺序保留，第一个节点是入口，节点顺序不建立隐式边。前言不属于任何节点，不进入默认模型输入。

DSL 表达 Config、节点、正文、非执行说明、执行引用及转移表。它不声明模型凭据、temperature、I/O 映射、State 字段类型或 Reducer 表达式。此类功能由 Host、外部代码和原生定义承担。

## 2. 字符、名称与 Markdown 上下文

输入按 UTF-8 解码，CRLF／CR 统一为 LF；源位置仍须能够对应输入文件。结构分隔符 HWS 仅为 ASCII 空格或制表符，不包括其他 Unicode 空白。

名称由至少一个 Unicode General Category 为 L*／N* 的码点或 `_`／`-` 组成，不包括组合标记 M*，不含空白。按原始码点比较，区分大小写、不归一化、不要求是 Python 标识符。节点名在文件内唯一，具名路由键在节点内唯一。`@` 前缀保留给语言标记。

Markdown 块与行内上下文采用 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)，管道表格边界采用 [GFM 表格扩展](https://github.github.com/gfm/#tables-extension-)；本规范的专门覆盖规则优先。其他 Markdown 只保留源文本，不要求渲染。

结构标记、设置及说明从顶层第 1 列识别，不通过全局去缩进激活标记。围栏代码、缩进代码、行内代码、HTML 原文块、普通引用及嵌套列表中的同形内容保持字面意义。顶层直接列表项是设置的合法位置，不能以“所有列表均忽略”代替上下文判断。顶层 `>>>` 是对普通引用的专门覆盖。

围栏须按 Markdown 规则闭合；未闭合围栏报错并定位开围栏。HTML 原文保留，不增加 HTML 注释移除或专用闭合检查。没有额外 DSL 转义转换；展示字面标记推荐使用闭合代码块。

## 3. 行语法

以下 EBNF 只作用于允许识别的位置，不含行尾；末行允许没有换行。

```ebnf
HWS          = " " | "\t" ;
HWS0         = { HWS } ;
HWS1         = HWS, { HWS } ;
NAME_CHAR    = Unicode_Letter | Unicode_Number | "_" | "-" ;
NAME         = NAME_CHAR, { NAME_CHAR } ;
NODE         = "#", HWS1, ("[Node]" | "[ToolNode]" | "[Subgraph]"), HWS1, NAME, HWS0 ;
CONFIG       = "#", HWS1, "[Config]", HWS0 ;
TRANSITIONS  = "##", HWS1, "[Transitions]", HWS0 ;
SETTING      = "-", HWS1, "**@", KEY, "**", HWS0, ":", HWS0, VALUE ;
KEY          = "host" | "state" | "uses" | "router" | "tools" | "trace" | "source" ;
DESCRIPTION  = ">>>", REST_OF_LINE ;
ROUTE_KEY    = NAME | "@Default" | "@ToolCalls" | "@Otherwise" ;
TARGET       = NAME | "@End" ;
LIST_RECORD  = "-", HWS1, ROUTE_KEY, HWS0, "->", HWS0, TARGET, HWS0 ;
BLANK        = HWS0 ;
```

VALUE 是裁剪外侧 HWS 后非空的单行字符串；REST_OF_LINE 可为空。结构 token 内不允许插空，token 之间可有多个 HWS。保留标题后不接受额外内容、注释或 Markdown 标题闭合符。

`# [node] A`、`# [Graph]` 是普通标题，不模糊纠正。`# [Node]` 是缺少名称的保留结构，必须报错；`# [Node] A B` 是非法名称。

```markdown
#   [Node]   Analyze
-   **@uses** :   python:./tools_cn.py:run
##   [Transitions]
- @Default->@End
```

以上是合法空白变体。

## 4. 文件区域与识别顺序

```text
文件 = 前言 + 可选 Config + 一个或多个 Node
Config = Config 标题 + 配置设置／说明／普通前言
Node = Node 标题 + 正文／节点设置／说明 + 可选 Transitions
Transitions = Transitions 标题 + 列表记录区 或 单一表格区
```

Config 至多一个，必须位于首节点之前，其范围到首节点。没有隐式 Config。节点范围到下一节点或 EOF；Transitions 至多一个，是节点最后区块，到下一节点或 EOF，不需要闭合标记，也不恢复正文。

识别顺序：

1. 解码并规范化换行，保留源位置映射。
2. 确定 Markdown 字面量与容器上下文。
3. 在允许位置识别 Node、Config、Transitions，建立范围。
4. 在前言、Config 或节点正文区识别设置起点，并检查作用域。
5. 在上述范围识别顶层 `>>>` 说明。
6. 剩余原文保留为前言或节点正文；提取结果不得再次激活 DSL。

Transitions 内只接受对应记录格式及允许的空白行。重复标题、设置、独立说明、正文或其他标题均报错；合法下一 Node 标题是边界。

## 5. 设置

设置形式为 `- **@KEY**: VALUE`，区分大小写。仅裁剪值外侧 HWS，不求值、不展开环境变量、不自动去引号。

| 设置 | 作用域 | 意义 |
| --- | --- | --- |
| @host | 显式 Config | 启动器选择 Host 引用 |
| @state | 显式 Config | 构建前选择原生 State Schema 引用 |
| @trace | 显式 Config | 实验性节点与路由记录；值为 `on` 或 `off` |
| @source | Subgraph | 必需的子图文件路径，不带执行器前缀 |
| @uses | 节点正文区 | 选择 Hardcode_Execution_Backend 及执行引用 |
| @router | 节点正文区 | 节点结束时取得路由键的执行引用 |

节点设置可与正文、空行、说明穿插，直到 Transitions；没有“属性区关闭”。同一作用域不得重复同一设置。

设置检查起点是允许识别位置、第 1 列 `-`、HWS1、紧随 `**@`。进入检查后，未知键、缺闭合粗体、缺冒号、空值、重复或错误作用域必须报错，不退回正文。`- @uses: ...`、`- **uses**: ...`、`- **重点** ...` 为普通文本。

```markdown
# [Config]
- **@state**: python:./state_cn.py:State

# [Node] Prepare
- **@uses**: pyfunction:./tools_cn.py:prepare

根据提供的材料回答问题。

## [Transitions]
- @Default -> @End
```

Config 不接受模型配置、任意 host.* 参数或输入输出表达式。文件级执行器选择需求暂缓，不定义对应键。

## 6. 正文、说明与精确提取

节点正文是原始 Markdown，不按渲染结果重写。顶层行首 `>>>` 每行独立表示非执行说明，移除其前缀及紧随的至多一个 ASCII 空格，保留说明文本供审计。下一行未以该标记开始即恢复普通正文。说明不进入默认模型输入，不表示关闭模型调用。

正文提取算法：

1. 取得 Node 标题后、Transitions 前的规范化源行；无 Transitions 时到节点末尾。
2. 已提取设置行和说明行分别替换为一条空字符串行，保留行位置。
3. 删除两端仅含 ASCII 空格或制表符的空白行。
4. 内部行逐字保留，以 LF 连接；不增加额外末尾 LF。全为空白时得到空字符串。

```markdown
# [Node] A
第一行
- **@uses**: python:./tools_cn.py:run
>>> 说明
第二行  

## [Transitions]
- @Default -> @End
```

该正文的 JSON 表示为 `"第一行\n\n\n第二行  "`；末行两个空格保留。代码、普通引用、嵌套列表内的同形标记和未解码实体／反斜杠原样保留。原文、设置、说明及位置另外保存，正文不是唯一解析产物。

空正文和只有说明的节点在语法上合法。默认 Prompt 不因此跳过模型。对所有 Hardcode_Execution_Backend，框架统一提供正文，不按执行方式做“正文存在即非法”的检查；使用、忽略或拒绝由其实现决定。内置策略见白皮书。

## 7. 转移表的语法

每个 Transitions 必须至少一条记录，只采用列表或一张管道表，不可混用。

```markdown
## [Transitions]
- ready -> Report
- missing -> RequestMaterial
```

```markdown
## [Transitions]
| 路由 | 目标 | 说明 |
| --- | --- | --- |
| ready | Report | 材料足够 |
| missing | RequestMaterial | 请求补充 |
```

两种形式语义相同。列表记录可由空行隔开，不接受嵌套记录、行内注释或尾部额外文本。

表格规则：

- 表头、分隔行、记录行从第 1 列开始；两侧外部竖线可省略，边界及转义竖线按 GFM 处理，不能简单切割每个竖线。
- 表头至少两列，分隔行列数相同；每列可有两侧冒号，中间至少一个 `-`，外侧 HWS 可忽略。
- 至少一条数据记录，每条实际提供至少两列。前两列裁剪 HWS 后分别符合 ROUTE_KEY／TARGET，不接受空列、粗体、链接、行内代码或名称反转义。
- 第三列及以后不限内容和列数，超过表头列数也不得丢弃；全部原文保留，不参与执行或默认模型输入。
- 数据记录连续，不允许中间空行。表格前后可有空白行；表结束后再次出现记录或表头报错，不续表、不创建第二张表。
- 表头标签、对齐方式无执行语义；表前后不得夹带普通正文。
- 不提供 >>> 注释：独立行报错，前两列按名称规则校验，附加列中的字面 >>> 不再解析。

## 8. 图控制流语义

| 形式 | 含义 |
| --- | --- |
| @Default → TARGET | 唯一无条件边，不能与具名键混用，不是失败兜底 |
| NAME → TARGET | 条件键到目标的映射，单条记录仍然是条件边 |
| TARGET 为 @End | 当前 DSL 路径不再调度后继，不取消原生其他分支 |
| 无 Transitions | 没有 DSL 后继；语法合法但不推荐作教学写法 |

允许前向引用、自环、循环、不可达节点、多个键指向同一目标；不强制有可达终点。目标节点必须存在。其他 @ 标记非法；Default／END 不是别名，符合名称规则时只是普通名称。没有 `- @End` 简写。

正式示例和创建工具推荐明确写 `- @Default -> @End`；没有转移表的节点保留为边界样本，不要求解释器警告。

有有效 @router 的条件节点必须遵循：节点执行 → 原生 Reducer 合并更新 → router 读取合并后的 State → 返回键 → 精确校验并查表 → 调度。router 不另占 DSL 节点，不提供业务 State 更新，返回值不是目标节点名。uses／router 共用引用接入，挂载位置由构建器决定。

无表或无条件表上的 router 语义无效；首版允许延后专项检查，但不承诺执行未用于选路的 router。未提供 router 时由执行实现明确提供路由值，不猜任意返回值或原生 goto。默认模型节点的文本选路见白皮书。

非法键报运行错误，不猜测、不修复、不默认重试、不额外调用模型；@Default 不能兜底。

原生 Callable 可以自行使用跳转能力，默认不封禁表外目标。原生跳转不取消 DSL 出边；两者可能同时调度。构建器不得把 goto 自动当作替代表内边或键，也不得在实现同一条 DSL 边时重复调度。更复杂原生调度遵循原生能力，具体兼容性必须验证，不承诺对用户重复目标自动去重。

## 9. State、引用与扩展边界

State 和 Reducer 采用原生定义，不进入 DSL 类型语法。用户可扩展或完全替换默认定义；框架不得补回默认字段、Reducer，改写注解或另行重做合并。纯 Callable 图不必有 messages；依赖消息的默认模型节点必须取得兼容 State 或用户适配，不能偷偷建立另一份 State。其他 State 字段不自动成为模型输入。

引用在语言层是完整字符串及位置，解析器不导入、不执行、不验证入口对象存在性，不强制最后一段是 Python 函数名。内置文件解释见白皮书。相对文件以 DSL 来源目录为基准，不修改进程 cwd；内存来源需由宿主明确基准，但内存解析公开入口尚未定义。

宿主显式定义优先于文件声明，文件声明优先于默认值；实际未选中的引用不必先导入，原声明保留审计。选中引用失效必须报错，不猜模块、不自动降级执行方式。

声明 @uses 后，执行权交给所选执行器，框架不在其前后额外 invoke。框架保留原生同步／异步、运行参数及特殊返回的接入通道，不把所有 Callable 收窄为材料函数或统一自研封套。具体接口与默认能力见白皮书。

## 10. 诊断要求

诊断至少含阶段、简明原因和源位置。引用错误指出原始引用；路由错误指出节点、返回键、合法键。不冻结异常类或错误码，不要求多错误文件的诊断顺序固定。

| 阶段 | 必须报告的错误 |
| --- | --- |
| 解析／静态 | 无节点；名称非法／重复；Config 重复／错位；Transitions 重复／位置错误；围栏未闭合 |
| 解析／静态 | 设置格式、键、值、重复或作用域错误 |
| 解析／静态 | 空转移区；格式混用；第二张表；表格中断后恢复；缺执行列；额外正文／独立说明 |
| 解析／静态 | 键非法／重复；目标非法／不存在；未知特殊标记；@Default 与具名键混用 |
| 绑定／构建 | 选中引用无法加载／槽位不兼容；执行方式缺失；实际需要的模型或 State 契约不兼容 |
| 绑定／构建 | 内置 python 条件表无 router 且无明确的键提供协议 |
| 运行 | 路由值不合法；执行器／原生运行错误按各自契约报告 |

全部节点读取后检查目标，以支持前向引用。只读解析不能为诊断引用而导入代码。执行器主动拒绝正文是其自身能力错误，不是统一的 DSL 语法错误。

## 11. 暂缓功能

首版不定义：文件级 Hardcode_Execution_Backend 选择、模块引用、自定义模型输出 Schema 设置、材料保存关闭选项、专用转义、HTML 注释功能、@failed、重试恢复语法、DSL 并行分发、模型或 I/O 配置表达式。

这些不是隐藏功能；未知设置仍报错。暂缓 DSL 表达不限制 Host 或原生 Python 使用其已有能力，不形成通用权限或控制流封禁。

## 工具调用扩展（2026-10-09）

本节新增 ToolNode、@tools 和两个保留路由条件；此前属性白名单与条件键规则据此扩展。既有示例行为不变，多模型声明和 MCP 连接配置不属于此扩展。

工具节点标题为 `# [ToolNode] NAME`，名称约束、源码位置、入口顺序、目标引用与普通 `# [Node] NAME` 相同，两个类型共享名称空间。GraphSpec 的 NodeSpec.kind 为 Node 或 ToolNode。标题在代码围栏和 Markdown 容器中仍视为正文。

ToolNode 必须声明一次 `- **@tools**: all` 或 `- **@tools**: [name, name]`。列表允许逗号周围空白和空列表；名称由 ASCII 字母、数字、下划线、连字符组成，大小写敏感，不支持引号、尾逗号、重复名称或 list: 前缀。all 表示本次构图显式传入的全部工具，不执行服务发现。缺失工具名和外部重名在绑定阶段报错。@tools 仅允许在 ToolNode 内；ToolNode 允许 @router，不允许 @uses。工具节点正文保留在 NodeSpec，但原生工具执行不使用正文，不调用模型。不要在正文放置预期模型遵循的指令。

跳转表（列表与表格均适用）新增：
- `@ToolCalls`：读取节点更新经 reducer 合并后的 State.messages；最后一条为 AIMessage 且 tool_calls 非空时匹配。
- `@Otherwise`：其余条件未匹配时的兜底。它不吞掉执行器或 router 异常。
- `@Default` 仍只能单独出现，为无条件边，不能与以上条件混用。

出现特殊条件的表使用以下顺序，与书写顺序无关：
1. 已声明且匹配 @ToolCalls 时直接使用表内目标，跳过 @router。
2. 否则调用显式 @router；无 router 的内置模型节点使用合并后最新 AIMessage 的去首尾空白文本作为普通路由键。
3. 普通路由键匹配成功则跳转，否则使用 @Otherwise；无兜底则抛路由错误。

特殊条件由运行数据判定，模型输出字面文本或 router 返回字符串 "@ToolCalls" 不会伪造该信号。非内置模型执行器如有普通条件键仍须声明 router；只有特殊条件则不要求 router。没有特殊条件的表保留原有路由行为。工具请求不会自动生成边；缺少 @ToolCalls 不会自动执行工具。

工具节点执行一条 AIMessage 中的全部调用；不隐式按名称拆分多个工具节点，不自动返回调用者。其后继由跳转表决定。用户原生 Command 能力继续保留，DSL 不额外封禁。

本扩展使用标准 messages 通道，框架不修复自定义 reducer，也不保证修改或删除工具消息后的协议仍可运行。

## 内置交互执行器补充（2026-10-09）

`- **@uses**: request_input:提示文本` 是既有执行引用的内置实现，不新增 DSL 结构语法。引用是单个物理行；双引号不创建跨行设置。可选 JSON 字符串解码（例如 `\n`）由 request_input 执行器负责，解析器保留原文。参数、回复及 State 更新约定见[白皮书](IMPLEMENTATION_WHITEPAPER_cn.md)末尾 request_input 一节。

## 可选沙箱执行器补充（2026-10-09）

`- **@uses**: monty:./program.py`（或同形式的 @router）是已有执行引用槽位的可选内置实现，不新增 DSL 关键字、节点种类或 Reducer 语法。文件 payload 与返回约定由 monty 执行器负责，见[白皮书](IMPLEMENTATION_WHITEPAPER_cn.md)末尾。

## 实验性扩展：执行记录（2026-10-17）

```markdown
# [Config]
- **@trace**: on
```

`@trace` 只允许出现在显式 Config 中。按普通规则裁剪外侧水平空白后，值仅为不加引号的小写 `on` 或 `off`；省略等同 `off`。放在 Node/ToolNode、重复声明或使用其他值均为解析错误。首版没有节点级覆盖或 DSL 保存路径。

`on` 请求观察 DSL 节点执行和路由，需要受支持的运行接收器。执行入口不支持接收时必须明确失败，不能静默丢弃请求的记录。原生 builder 构建本身不执行图，可以在执行时检查接收器。具体公共 API 与 Host 接入见实现白皮书。

记录保存在业务 State 和 messages 之外；不选择 reducer、不改变路由键、不增加边、不调用模型，也不自动成为模型记忆。节点正常完成仍可能返回失败路由；选定目标不代表目标已经执行。原生中断保持其语义，记录时与执行异常区分。并行完成顺序不能被解释成依赖路径。

运行记录关联源图版本、DSL 节点名、每次执行、执行结果、更新字段名及观察到的路由决定。不自动推断业务正确性。可选短摘要必须由应用显式提供，默认不采集完整 State、Prompt 或消息内容。Host 负责收集、保存及呈现给模型的简短反馈。


## 子图引用扩展（2026-10-17）

```markdown
# [Subgraph] Research
- **@source**: ./research.md
>>> 此处执行整个子图，结束后继续父层流程。

## [Transitions]
- @Default -> Report

# [Node] Report
根据已有结果生成报告。

## [Transitions]
- @Default -> @End
```

`Subgraph` 是父图中的节点种类，名称、入口位置、局部目标解析和区块边界与 Node 一致。其设置仅为必需且唯一的 `@source` 与可选 `@router`。不接受 @uses、@tools、@state、@host 或 @trace；它不是 Config 的替代写法。子图节点无 Prompt 语义，提取后的普通正文非空时报错；作者说明使用 `>>>`。子文件内部普通 Node 的正文规则不变。

`@source` 是原始文件路径，不带 backend 前缀或 :ENTRY。必须以 ./、../ 开始，或为当前平台的绝对路径。路径内部空格允许，不展开 ~、环境变量或引号。相对路径以声明该设置的文件目录为基准。引用文件按 UTF-8 SkilledGraph 文件解析，不要求文件扩展名；子文件内部的引用仍相对于子文件。parse_graph 与 --check 只检查当前文件，不递归读取引用或导入代码。构建阶段才读取全部子图依赖，报告文件错误、子图解析错误或引用环。

每个文件定义独立的图和节点名称作用域。不同文件可有同名节点；同一父文件内 Node、ToolNode、Subgraph 名称不能重复。父层普通转移表只能指向当前图的节点或 @End，不能引用子图内部名称。子图从其首节点开始，子图 @End 结束子图路径；正常完成后返回父层，执行调用节点的 router（若有），再按父层转移表继续。具名条件路由要求显式 router，不自动读取子图末条回复当路由键；现有 @ToolCalls/@Otherwise 信号规则仍可观察父层合并后的 messages。

子图用自己的 Config @state；省略时用默认 MessagesState，不继承父图 Schema。父子图按原生共享字段和 reducer 规则交换数据，不构成一个全局可变 State。Subgraph 不提供字段映射、Schema 覆盖、私有历史适配或额外模型调用。需要转换时使用原生 Python 节点。子文件 @host 仅独立启动该文件时有效，被引用时不执行。

同一文件可被多处引用并具有独立调用身份；不复用可变运行状态。构建期文件递归引用（包括符号链接别名）报错并显示链路；转移表形成的运行循环仍然允许。一次构建加载的源定义固定，后续文件编辑仅在重新构建时生效；不提供热替换或内联嵌套定义。

每个文件的 @trace 开关独立：父图开启不自动开启子图，父图关闭也不禁止子图开启。只要任意被引用图开启追踪，执行就需要接收器。记录带调用路径、源文件版本和父执行关联，不能将同一子图的多次调用混为一条执行。具体 API、资源和持久化边界见白皮书。
